Proof rule

Upstream changes erase downstream confidence.

A green check proves one exact source, plan, editor save, or render. It does not survive a change to the thing it measured.

Source or intake changes Recheck everything Gates 0–5 reopen
Story, A-cut, or timing changes Rebuild visuals onward Gates 1–5 reopen
Asset, text, or audio changes Reassemble and rerender Affected Gate 2 + Gates 3–5 reopen
Editor save or export changes Old render proof expires Gates 3–5 reopen

Weekly lifecycle

The export inbox is a conveyor belt, not storage.

Once a file is stable enough to classify, it must leave incoming with a receipt—accepted or unresolved.

  1. 1 Incoming Fresh top-level editor exports only
  2. 2A By-week final Unambiguous, accepted, canonically named
  3. 2B Needs review Stable but ambiguous, with a reason note
  4. 3 Posting audit Owned-platform match, link, date, exception
  5. 4 Views Completed or carryover symlinks from status
NEW INVARIANT

A stable old file may not silently remain in incoming. Classify it, quarantine it with evidence, or raise a blocker. Never guess the destination.

One decision before any consolidation

Should one video toolkit own the overlapping code?

Recommended: keep private state, media, Showroom, CapCutBot, and platform bots separate. Consolidate the A-cut engine and browser editor as packages/apps under the video-operations toolkit only after every history and dirty-work receipt is frozen.

  • One canonical internal video-code home
  • No collapse of privacy or deployment boundaries
  • No move until unpushed work and compatibility paths are preserved
